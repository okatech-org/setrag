voyageur-mobile — application voyageur

L'application Expo du voyageur : acheter, porter et présenter son billet — y compris sans réseau, dans le train. Même parcours d'achat que le web, adapté au contexte gabonais : paiement mobile money natif, billet par SMS, consommation de données minimale.

Expo SDK 57 iOS + Android OTP téléphone → plan backend

1Mission & contraintes

  • Le billet vit dans le téléphone : une fois émis, il est consultable et présentable sans aucune connexion — cache local systématique, exigence explicite du CDC front-office (« utilisation hors ligne partielle »).
  • Application légère : taille d'installation limitée et faible consommation de données et de batterie (exigences CDC) — pas de bibliothèque lourde, images compressées, temps réel WebSocket plutôt que polling.
  • Le téléphone est l'identité : session par OTP SMS via Better Auth (phoneNumber + client Expo, jeton en expo-secure-store) ; l'état de session se lit via useConvexAuth(), le profil via la query users:me.

2Écrans

Accueil — recherche rapide (gares mémorisées), prochains départs, statut temps réel des dessertes du jour trips.search · trips.listUpcoming
Tunnel d'achat — mêmes étapes que le web (résultats → passagers → paiement) en navigation native ; paiement mobile money avec écran d'attente réactif du push USSD ; option « payer au guichet » bookings.create · payments.initiate · fares.quote
Mes billets — onglet central : billets à venir et passés, code-barres Aztec plein écran avec luminosité forcée, disponible hors-ligne tickets.listMine + cache local
Suivi du voyage — statut de la desserte (retard, annulation) en temps réel, rappels de départ trips.get (abonnement réactif)
Notifications — centre de notifications, préférences par canal notifications.list · pushTokens.register
Compte — profil, consentements, langue ; connexion OTP SMS users.me · consents.*

3Billet hors-ligne & anti-fraude

  • Cache local des billets : payload, signature et rendu Aztec stockés au moment de l'émission — le billet s'affiche dans le train sans réseau, le contrôleur le vérifie par signature (voir plan contrôleur).
  • Code dynamique : en ligne, le code affiché est régénéré périodiquement ; hors-ligne, le dernier code émis reste valable — le partage d'une capture est détectable par l'anti-repassage du contrôleur.
  • Capture d'écran bloquée sur l'écran du billet (FLAG_SECURE Android, détection iOS).
  • Billet par SMS en secours : la référence + lien court arrivent aussi par SMS à l'achat — un voyageur sans l'application (ou avec un téléphone simple) présente la référence, contrôlable via le manifeste embarqué du contrôleur.
