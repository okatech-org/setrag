controleur-mobile — application contrôleur

Nouvelle application Expo, offline-first par conception : le hors-ligne est le mode nominal en pleine voie (tunnels, forêt), pas un mode dégradé. Scan des billets et abonnements, vente à bord, procès-verbaux avec encaissement d'amendes, signalement d'incidents — le tout en file locale synchronisée au retour du réseau.

Expo (build natif) Offline-first MFA obligatoire → plan backend

1Mission & principe

Convex ne fournit pas de mode hors-ligne persistant : la couche locale est construite. Principe directeur — tout ce qui est nécessaire au contrôle est embarqué avant le départ, tout ce qui est produit à bord est journalisé localement puis synchronisé de manière idempotente.

  • Le billet est auto-porteur : signature Ed25519 vérifiable localement (authenticité, desserte, segment, expiration) sans aucune donnée réseau.
  • Le manifeste embarqué complète la vérification : statut fin (annulé, remboursé), voyageurs attendus, référence présentée par SMS.
  • Chaque écriture locale (scan, vente, PV, incident) porte un clientId unique et entre dans la file d'envoi dans la même transaction SQLite que l'écriture métier.

3Cycle d'une tournée

  actor C as Contrôleur
  participant APP as App (SQLite chiffré)

  Note over C,CX: Avant le départ — réseau disponible
  C->>APP: connexion + TOTP · sélection de la desserte
  APP->>CX: tickets.manifest(tripId) — paginé
  CX-->>APP: manifeste + clé publique + barème amendes + stock vente à bord
  APP->>APP: stockage local chiffré

  Note over C,APP: En voyage — souvent sans réseau
  C->>APP: scan Aztec (billet ou abonnement)
  APP->>APP: vérif Ed25519 + desserte/segment + expiration
  APP->>APP: anti-repassage + croisement manifeste
  APP->>APP: résultat net : VALIDE / INVALIDE (+ motif)
  C->>APP: régularisation : vente à bord OU procès-verbal
  APP->>APP: écriture métier + file d'envoi (même transaction, clientId)

  Note over APP,CX: Retour du réseau — automatique
  APP->>CX: scans/pv/ventes/incidents .syncBatch (idempotent)
  CX-->>APP: états consolidés · conflits signalés
  APP->>APP: purge locale après desserte terminée + sync confirmée

4Écrans

Connexion + MFA — identifiant interne, TOTP, session courte ; verrouillage par code après inactivité Better Auth twoFactor
Tableau de bord — desserte du jour, téléchargement du manifeste, état de synchronisation, indicateur de fraîcheur des données embarquées trips.listUpcoming · tickets.manifest
Scanner — plein écran, résultat en une seconde : VALIDE (vert, nom du voyageur, destination) ou INVALIDE (rouge, motif : signature, desserte, segment, expiré, déjà contrôlé, annulé) vérification locale + scans.syncBatch
Recherche manuelle — par référence (billet SMS) ou nom, dans le manifeste embarqué manifeste local
Vente à bord — trajet restant, classe, tarif du barème, encaissement espèces (ou mobile money à la reconnexion), billet affiché à l'écran ou référence transmise par SMS sales.createOnboard (via sync)
Procès-verbal — motif (sans titre, titre invalide, classe), identité du contrevenant, montant du barème embarqué, encaissement immédiat ou différé pv.syncBatch
Signalement d'incident — catégorie, gravité, description, photos ; les incidents critiques partent en priorité à la reconnexion incidents.syncBatch
Historique & synchronisation — contrôles de la tournée, file d'envoi (en attente / envoyé / en échec), écran de conflits à arbitrer scans.listByAgent

5Conflits & sécurité

  • Conflits : signaler, ne pas bloquer. Un billet validé hors-ligne sur deux terminaux remonte en conflit à la synchronisation — le système ne peut pas distinguer une fraude d'un second contrôle légitime, l'arbitrage est humain (écran dédié, PV possible a posteriori).
  • Anti-repassage local : un même titre scanné deux fois sur le même terminal dans la fenêtre de la tournée est signalé immédiatement.
  • Minimisation : le manifeste embarqué ne contient que le nécessaire au contrôle ; purge complète après tournée synchronisée ; base chiffrée ; aucune donnée voyageur dans les journaux applicatifs.
  • Traçabilité : chaque contrôle est horodaté, géolocalisé si disponible, rattaché à l'agent et au terminal — la journalisation des contrôles est une exigence des deux CDC.
